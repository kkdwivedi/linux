The verifier rejects the program at the first instruction:

```text
0: (85) call bpf_ktime_get_coarse_ns#160
program of this type cannot use helper bpf_ktime_get_coarse_ns#160
```

The program is loaded from:

```c
SEC("kprobe")
```

so it is a kprobe program. For this program type, the verifier’s helper whitelist does not allow `bpf_ktime_get_coarse_ns()`. The instruction itself is well-formed, and the rest of the program is trivial, but helper availability is checked per program type before execution analysis can continue.

The smallest likely source-level fix is to use the regular ktime helper, which is allowed for kprobe programs:

```c
bpf_ktime_get_ns()
```

The program ignores the helper return value anyway because it immediately does:

```asm
r0 = 0;
exit;
```

so replacing the coarse helper with the normal ktime helper preserves the observable behavior of returning `0`.

Patch:

```diff
diff --git a/case.c b/case.c
index 0000000..0000000 100644
--- a/case.c
+++ b/case.c
@@ -8,10 +8,10 @@ SEC("kprobe")
 __naked void entry(void)
 {
 	asm volatile ("					\
-	call %[bpf_ktime_get_coarse_ns];		\
+	call %[bpf_ktime_get_ns];			\
 	r0 = 0;						\
 	exit;						\
 "	:
-	: __imm(bpf_ktime_get_coarse_ns)
+	: __imm(bpf_ktime_get_ns)
 	: __clobber_all);
 }
```

This should satisfy the verifier because `bpf_ktime_get_ns()` is a helper permitted for kprobe programs, unlike `bpf_ktime_get_coarse_ns()` in this verifier configuration.
