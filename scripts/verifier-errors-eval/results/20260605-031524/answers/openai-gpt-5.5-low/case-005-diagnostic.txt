The verifier rejects the program because `bpf_copy_from_user()` is a sleepable helper, and the program calls it while preemption is disabled:

```c
bpf_preempt_disable();              // enters non-preemptible region, depth 1
bpf_copy_from_user(...);            // may sleep: not allowed here
bpf_preempt_enable();
```

In a non-preemptible region, the verifier forbids helpers/kfuncs that may sleep. The log is explicit:

```text
sleepable helper bpf_copy_from_user#148 in non-preemptible region
```

The earlier line:

```text
arg#0 reference type('UNKNOWN ') size cannot be determined: -22
```

does not appear to be the actual rejection reason here; the verifier continues and rejects specifically at the helper call due to execution-context safety.

The smallest source-level fix is to move `bpf_copy_from_user()` outside the preemption-disabled section, or remove the preemption-disable region entirely if it is not needed.

A minimal patch preserving the calls would be:

