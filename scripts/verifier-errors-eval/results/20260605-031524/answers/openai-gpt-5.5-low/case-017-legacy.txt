The verifier failure is due to the required ordering for `bpf_local_irq_save()` / `bpf_local_irq_restore()` pairs.

Each `bpf_local_irq_save(&flags)` creates a verifier-tracked IRQ state reference. These references must be restored in strict LIFO order, like a stack.

In the program:

```c
bpf_local_irq_save(&flags1);    // creates ref id=1
bpf_local_irq_save(&flags2);    // creates ref id=2

bpf_local_irq_restore(&flags1); // tries to restore id=1 first
bpf_local_irq_restore(&flags2);
```

The verifier expects `flags2` to be restored first, because it was the most recent IRQ save. The log confirms this:

```text
cannot restore irq state out of order, expected id=2 acquired at insn_idx=7
```

So the smallest fix is to restore in reverse order:

```c
bpf_local_irq_restore(&flags2);
bpf_local_irq_restore(&flags1);
```

Patch:

```diff
diff --git a/case.c b/case.c
index 0000000..0000000 100644
--- a/case.c
+++ b/case.c
@@ -8,8 +8,8 @@ int entry(struct __sk_buff *ctx)
 
 	bpf_local_irq_save(&flags1);
 	bpf_local_irq_save(&flags2);
-	bpf_local_irq_restore(&flags1);
 	bpf_local_irq_restore(&flags2);
+	bpf_local_irq_restore(&flags1);
 	return 0;
 }
```

Fixed source:

```c
#include <vmlinux.h>
#include <bpf/bpf_helpers.h>

SEC("?tc")
int entry(struct __sk_buff *ctx)
{
	unsigned long flags1, flags2;

	bpf_local_irq_save(&flags1);
	bpf_local_irq_save(&flags2);
	bpf_local_irq_restore(&flags2);
	bpf_local_irq_restore(&flags1);
	return 0;
}
```

This should satisfy the verifier because the IRQ state references are released in the reverse order in which they were acquired.
