The verifier rejects the program because the 4th argument to `bpf_dynptr_slice()` is the size of the backing buffer passed in arg 3:

```c
hdr = bpf_dynptr_slice(&ptr, 0, buffer, slice_len);
```

`buffer` is a stack buffer of only `sizeof(struct ethhdr)` bytes, but `slice_len` is a mutable global variable:

```c
__u32 slice_len = sizeof(struct ethhdr);
```

Because it lives in writable `.data`, the verifier cannot assume it is still `sizeof(struct ethhdr)` at runtime. In the log:

```text
11: R4 = *(u32 *)(r1 +0)
...
R4=scalar(smin=0,smax=umax=0xffffffff)
...
R4 unbounded memory access
R3 and R4 memory, len pair leads to invalid memory access
```

So the verifier sees `R4` as potentially any `u32`, including values much larger than the stack buffer at `R3 = fp-32`. That makes the helper call unsafe.

The smallest robust fix is to pass a verifier-known constant size for the stack buffer, e.g. `sizeof(buffer)`, instead of the mutable global.

Patch:

```diff
diff --git a/case.c b/case.c
index 0000000..0000000 100644
--- a/case.c
+++ b/case.c
@@ -9,8 +9,6 @@ struct {
 	__uint(max_entries, 4096);
 } ringbuf SEC(".maps");
 
-__u32 slice_len = sizeof(struct ethhdr);
-
 SEC("?tc")
 int entry(struct __sk_buff *skb)
 {
@@ -23,7 +21,7 @@ int entry(struct __sk_buff *skb)
 
 	bpf_dynptr_from_skb(skb, 0, &ptr);
 
-	hdr = bpf_dynptr_slice(&ptr, 0, buffer, slice_len);
+	hdr = bpf_dynptr_slice(&ptr, 0, buffer, sizeof(buffer));
 	if (!hdr)
 		return SK_DROP;
 
```

Alternatively, if `slice_len` must remain variable, it needs an explicit bounds check before the helper call:

```c
__u32 len = slice_len;

if (len > sizeof(buffer))
	return SK_DROP;

hdr = bpf_dynptr_slice(&ptr, 0, buffer, len);
```

But if the intended slice size is always one Ethernet header, using `sizeof(buffer)` directly is the smallest and cleanest verifier-friendly fix.
