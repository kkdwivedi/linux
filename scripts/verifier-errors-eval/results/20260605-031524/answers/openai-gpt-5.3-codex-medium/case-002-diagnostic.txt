The verifier error is a classic **owned kptr lifetime leak**.

### What failed

`bpf_cpumask_create()` returns an owned `struct bpf_cpumask *` reference.  
In `make_object()`:

- If allocation fails: returns `NULL` (no ownership).
- If sanity check fails: releases and returns `NULL`.
- On success: returns a **live owned reference** to caller.

Then in `entry()` you do:

```c
cpumask = make_object();
__sink(cpumask);
return 0;
```

No release happens on the success path, so verifier reports:

- acquired resource at insn 0 (`bpf_cpumask_create`)
- exits with resource still live (`Unreleased reference id=2`)

### Smallest fix

Release in `entry()` on non-NULL pointer before exit.

### Patch

```diff
 SEC("tp_btf/task_newtask")
 int BPF_PROG(entry, struct task_struct *task, u64 flags)
 {
 	struct bpf_cpumask *cpumask;

 	cpumask = make_object();
 	__sink(cpumask);
+	if (cpumask)
+		bpf_cpumask_release(cpumask);

 	return 0;
 }
```

This satisfies verifier resource-lifetime rules: every acquired reference is released on all exit paths.
