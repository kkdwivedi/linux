The failure is caused by **stack slot type corruption**.

### What happens in your program

1. `*(u64 *)(r10 - 8) = r1`  
   Spills `r1` (a `ctx` pointer) into stack slot `[-8 .. -1]`.

2. `*(u8 *)(r10 - 7) = r0`  
   Writes a single byte **inside that same spilled 8-byte slot** (`-7` is within `[-8..-1]`).

3. Because of that partial overwrite, verifier marks the whole spilled value as unknown bytes (`fp-8=mmmmmmmm`).

4. Reload: `r0 = *(u64 *)(r10 - 8)` now gives `scalar()`, not `ctx`.

5. `r0 = *(u64 *)(r0 + 8)` tries to dereference a scalar → `R0 invalid mem access 'scalar'`.

---

### Smallest likely fix

Don’t write into the same stack slot as the spilled pointer.  
Change the byte store to a different offset (e.g. `r10 - 16`).

#### Patch

```diff
--- a/case.c
+++ b/case.c
@@ -7,7 +7,7 @@ __naked void entry(void)
 	asm volatile ("					\
 	*(u64*)(r10 - 8) = r1;				\
 	r0 = 0x23;					\
-	*(u8*)(r10 - 7) = r0;				\
+	*(u8*)(r10 - 16) = r0;				\
 	r0 = *(u64*)(r10 - 8);				\
 	r0 = *(u64*)(r0 + 8);				\
 	exit;						\
```

This preserves the spilled `ctx` pointer type across reload, which should clear the shown verifier error.
