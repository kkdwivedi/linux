The verifier is rejecting this because of **unbounded pointer arithmetic on a map value pointer**.

### What happens
- `r0` from `bpf_map_lookup_elem()` is `map_value` (size 48 bytes).
- `r3 = *(u32 *)(r0 + 0)` loads `offset` from the map value; verifier sees `r3` as `0 .. 0xffffffff`.
- `r1 = r0; r1 += r3` makes `r1` a map-value pointer with unknown offset up to 4GB.
- Then `bpf_probe_read_kernel(r1, 1, 0)` uses `r1` as destination buffer.
- Verifier must prove `offset + size <= 48`, but can’t (`offset` is unbounded), so it errors.

---

### Smallest likely fix
Add a bounds check on `r3` before `r1 += r3`, so verifier can infer `r3 <= 47` for a 1-byte write.

#### Patch
```diff
@@ SEC("tracepoint")
 	asm volatile ("					\
 	r2 = r10;					\
 	r2 += -8;					\
 	r1 = 0;						\
 	*(u64*)(r2 + 0) = r1;				\
 	r1 = %[map_a] ll;				\
 	call %[bpf_map_lookup_elem];			\
 	if r0 == 0 goto l0_%=;				\
 	r1 = r0;					\
 	r3 = *(u32*)(r0 + 0);				\
+	if r3 > 47 goto l0_%=;				\
 	r1 += r3;					\
 	r2 = 1;						\
 	r3 = 0;						\
 	call %[bpf_probe_read_kernel];			\
 l0_%=:	exit;						\
 "	:
```

This is minimal and should satisfy the verifier’s requirement that destination address remains within the 48-byte map value for a 1-byte access.
