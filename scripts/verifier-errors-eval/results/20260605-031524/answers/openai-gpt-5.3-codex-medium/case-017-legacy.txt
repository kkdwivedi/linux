The verifier is rejecting this because `bpf_local_irq_save/restore` are tracked like nested acquisitions/releases, and they must be unwound in **LIFO order**.

In your code:

```c
bpf_local_irq_save(&flags1); // acquire id=1
bpf_local_irq_save(&flags2); // acquire id=2
bpf_local_irq_restore(&flags1); // tries to release id=1 first -> wrong
bpf_local_irq_restore(&flags2);
```

The log confirms that at the first restore it expected to restore the most recent save (id=2 from insn 7), not id=1:

> cannot restore irq state out of order, expected id=2 acquired at insn_idx=7

### Smallest fix

Restore in reverse order of save:

```diff
 SEC("?tc")
 int entry(struct __sk_buff *ctx)
 {
 	unsigned long flags1, flags2;

 	bpf_local_irq_save(&flags1);
 	bpf_local_irq_save(&flags2);
-	bpf_local_irq_restore(&flags1);
 	bpf_local_irq_restore(&flags2);
+	bpf_local_irq_restore(&flags1);
 	return 0;
 }
```

That should satisfy the verifier’s IRQ-state ordering rules.
