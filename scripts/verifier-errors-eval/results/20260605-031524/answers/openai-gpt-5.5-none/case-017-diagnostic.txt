The verifier is rejecting the program because the two IRQ-save resources are restored in the wrong order.

`bpf_local_irq_save()` creates a tracked IRQ-disabled region associated with the stack slot passed to it. These regions must be released in strict last-in, first-out order.

Current program:

```c
bpf_local_irq_save(&flags1);    // acquire id=1
bpf_local_irq_save(&flags2);    // acquire id=2

bpf_local_irq_restore(&flags1); // tries to restore id=1 first: invalid
bpf_local_irq_restore(&flags2);
```

At the first restore, the verifier expects the most recently saved IRQ state, `flags2`, to be restored first. Instead, the program restores `flags1`, so verification fails with:

```text
cannot restore irq state out of order, expected id=2 acquired at insn_idx=7
```

The smallest source-level fix is to restore the flags in reverse order:

```c
bpf_local_irq_restore(&flags2);
bpf_local_irq_restore(&flags1);
```

Patch:

```diff
diff --git a/case.c b/case.c
index 0000000..0000000 100644
--- a/case.c
+++ b/case.c
@@ -8,8 +8,8 @@ int entry(struct __sk_buff *ctx)
 
 	bpf_local_irq_save(&flags1);
 	bpf_local_irq_save(&flags2);
-	bpf_local_irq_restore(&flags1);
 	bpf_local_irq_restore(&flags2);
+	bpf_local_irq_restore(&flags1);
 	return 0;
 }
```

Fixed source:

```c
#include <vmlinux.h>
#include <bpf/bpf_helpers.h>

SEC("?tc")
int entry(struct __sk_buff *ctx)
{
	unsigned long flags1, flags2;

	bpf_local_irq_save(&flags1);
	bpf_local_irq_save(&flags2);
	bpf_local_irq_restore(&flags2);
	bpf_local_irq_restore(&flags1);
	return 0;
}
```

This should satisfy the verifier because the IRQ state saved second is restored first, matching the required LIFO resource lifetime discipline.
