The verifier rejects the program at the first instruction:

```text
0: (85) call bpf_ktime_get_coarse_ns#160
program of this type cannot use helper bpf_ktime_get_coarse_ns#160
```

This is not a register/state issue. It is a helper availability policy failure: the program is attached as:

```c
SEC("kprobe")
```

which creates a kprobe program, but the helper `bpf_ktime_get_coarse_ns()` is not allowed for this program type on the tested kernel. The verifier therefore fails immediately before analyzing the rest of the program.

The smallest source-level fix is to use a time helper that is allowed for kprobe programs. `bpf_ktime_get_ns()` is the standard monotonic time helper and is generally allowed for tracing/kprobe programs.

Patch:

```diff
diff --git a/case.c b/case.c
index 0000000..0000000 100644
--- a/case.c
+++ b/case.c
@@ -8,7 +8,7 @@ SEC("kprobe")
 __naked void entry(void)
 {
 	asm volatile ("					\
-	call %[bpf_ktime_get_coarse_ns];		\
+	call %[bpf_ktime_get_ns];			\
 	r0 = 0;						\
 	exit;						\
 "	:
-	: __imm(bpf_ktime_get_coarse_ns)
+	: __imm(bpf_ktime_get_ns)
 	: __clobber_all);
 }
```

Resulting source:

```c
#include <linux/bpf.h>
#include <bpf/bpf_helpers.h>

char _license[] SEC("license") = "GPL";

SEC("kprobe")
__naked void entry(void)
{
	asm volatile ("					\
	call %[bpf_ktime_get_ns];			\
	r0 = 0;						\
	exit;						\
"	:
	: __imm(bpf_ktime_get_ns)
	: __clobber_all);
}
```

Why this should pass: the program does not use the helper result, then sets `r0 = 0` and exits. Replacing the disallowed helper with an allowed kprobe-compatible helper removes the policy violation while preserving the structure of the test.
