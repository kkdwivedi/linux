The verifier is rejecting the program because of **stack usage across nested BPF-to-BPF calls**.

Each of these helpers allocates:

```c
volatile char buf[MAX_STACK] = {};
```

with:

```c
#define MAX_STACK 260
```

BPF stack is limited, and the verifier also checks the **combined stack depth of active call chains**. The failing chain is effectively:

```text
entry -> helper_c -> helper_b -> helper_a
```

`helper_c` has a 260-byte local buffer, and `helper_b` also has a 260-byte local buffer. With compiler alignment/spill overhead, their combined active stack usage is reported as:

```text
combined stack size of 3 calls is 544. Too large
```

The limit is 512 bytes, so 544 exceeds it.

`helper_d` is reported safe:

```text
Func#4 ('helper_d') is safe for any args that match its prototype
```

The failure is not due to argument types or pointer safety. It is purely stack depth.

The smallest likely source-level fix is to reduce the per-function buffer size so that the combined stack usage of the deepest call chain stays below 512 bytes. Since the verifier reports 544 bytes with `MAX_STACK = 260`, reducing `MAX_STACK` to 240 should leave enough room for alignment overhead:

```diff
-#define MAX_STACK 260
+#define MAX_STACK 240
```

Complete patch:

```diff
diff --git a/test.c b/test.c
index 0000000..1111111 100644
--- a/test.c
+++ b/test.c
@@ -1,7 +1,7 @@
 #include <linux/bpf.h>
 #include <bpf/bpf_helpers.h>
 
-#define MAX_STACK 260
+#define MAX_STACK 240
 
 static __attribute__((noinline))
 int helper_a(int val, struct __sk_buff *skb)
```

Why this should satisfy the verifier:

- The deepest problematic chain contains stack-using functions `helper_c` and `helper_b`.
- With `MAX_STACK = 260`, their combined stack plus alignment is 544 bytes.
- Reducing each buffer by 20 bytes should reduce the active combined usage by about 40 bytes.
- That brings the expected combined stack usage to roughly 504 bytes, below the 512-byte verifier limit.

If this is intended to remain a stress test near the stack limit, `MAX_STACK = 240` is a conservative minimal-style adjustment.
