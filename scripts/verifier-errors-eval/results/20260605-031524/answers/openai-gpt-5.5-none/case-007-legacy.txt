The failure is on the `bpf_dynptr_slice()` call:

```c
hdr = bpf_dynptr_slice(&ptr, 0, buffer, slice_len);
```

Verifier state:

```text
11: R4 = *(u32 *)(r1 +0)
...
16: call bpf_dynptr_slice
R4 unbounded memory access, use 'var &= const' or 'if (var < const)'
R3 and R4 memory, len pair leads to invalid memory access
```

`bpf_dynptr_slice()` has the relevant arguments:

```c
void *bpf_dynptr_slice(const struct bpf_dynptr *ptr, __u32 offset,
                       void *buffer, __u32 buffer__sz);
```

Here:

- `R3` is `buffer`, pointing to the stack object `char buffer[sizeof(*hdr)]`
- `R4` is `slice_len`
- `slice_len` is a mutable global variable in `.data`

Even though it is initialized as:

```c
__u32 slice_len = sizeof(struct ethhdr);
```

the verifier cannot assume it always has that value. Since it is writable global data, from verifier perspective its value can be any `u32`:

```text
R4=scalar(smin=0,smax=umax=0xffffffff)
```

So the helper call may copy up to `0xffffffff` bytes into a stack buffer that is only `sizeof(struct ethhdr)` bytes. The verifier rejects this as an unbounded memory access.

The smallest fix is to make the length argument a verifier-known constant, or otherwise bound it before passing it to the helper. Since the local buffer is exactly `sizeof(*hdr)`, the cleanest source-level fix is to pass `sizeof(*hdr)` directly instead of the mutable global.

Patch:

```diff
diff --git a/case.c b/case.c
index 0000000..0000000 100644
--- a/case.c
+++ b/case.c
@@ -18,7 +18,7 @@ int entry(struct __sk_buff *skb)
 
 	bpf_dynptr_from_skb(skb, 0, &ptr);
 
-	hdr = bpf_dynptr_slice(&ptr, 0, buffer, slice_len);
+	hdr = bpf_dynptr_slice(&ptr, 0, buffer, sizeof(*hdr));
 	if (!hdr)
 		return SK_DROP;
 
```

Alternatively, if the test specifically needs to keep using `slice_len`, add an explicit verifier-visible bounds check before the helper call:

```c
if (slice_len > sizeof(buffer))
	return SK_DROP;

hdr = bpf_dynptr_slice(&ptr, 0, buffer, slice_len);
```

But the smallest and most reliable fix is replacing `slice_len` with `sizeof(*hdr)`, because then the verifier sees a constant length matching the stack buffer size.
