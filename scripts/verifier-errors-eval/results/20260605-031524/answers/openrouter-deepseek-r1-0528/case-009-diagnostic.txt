The verifier failure occurs because `value->task` might be NULL when passed to `bpf_task_acquire()`, which requires a non-NULL pointer. The verifier cannot guarantee that `value->task` is non-NULL after `map_insert()` succeeds, as the `task` field is initialized to NULL and later set via `bpf_kptr_xchg()`, which the verifier doesn't track sufficiently.

### Minimal Fix
Add a NULL check for `value->task` before calling `bpf_task_acquire()` in the `entry` program:

```diff
 SEC("tp_btf/task_newtask")
 int BPF_PROG(entry, struct task_struct *task, u64 flags)
 {
 	struct task_struct *acquired;
 	struct map_value *value;
 
 	value = helper_a(task);
 	if (!value)
 		return 0;
 
+	if (!value->task)
+		return 0;
+
 	acquired = bpf_task_acquire(value->task);
 	if (!acquired)
 		return 0;
 
 	bpf_task_release(acquired);
 	return 0;
 }
```

### Explanation
- **Why it fails**: The verifier sees `value->task` as a `rcu_ptr_or_null_task_struct` (possibly NULL) due to its initialization path, but `bpf_task_acquire()` requires a non-NULL pointer.
- **How the fix works**: The added NULL check ensures `value->task` is non-NULL before the call, satisfying the verifier's requirement. This allows the verifier to refine the pointer type to non-NULL on the continuation path.
- **Minimality**: Only 3 lines are added directly at the point of failure, preserving existing logic while addressing the verifier's concern. No other changes are needed.
