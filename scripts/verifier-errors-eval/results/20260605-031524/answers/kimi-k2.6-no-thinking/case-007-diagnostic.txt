Looking at this verifier failure, let me analyze what's happening:

## The Problem

The verifier is rejecting the call to `bpf_dynptr_slice()` because of an issue with the **length argument (R4)**, not actually the memory pointer (R3) as the primary cause.

Looking at the verifier log:
- At instruction 11: `r4 = *(u32 *)(r1 +0)` - This loads `slice_len` from a map value
- The verifier shows: `R4=scalar(smin=0,smax=umax=0xffffffff,var_off=(0x0; 0xffffffff))`

The problem is that `slice_len` is a **global variable** (`__u32 slice_len = sizeof(struct ethhdr);`), which the verifier loads from a map. The verifier cannot determine its bounds at verification time - it sees R4 as an unbounded scalar (`0` to `0xffffffff`).

The `bpf_dynptr_slice()` helper requires:
- R3: pointer to buffer memory
- R4: length of that buffer

The verifier needs to ensure that the length (R4) doesn't exceed the actual memory available at R3. Since `slice_len` is loaded from a map value, the verifier treats it as potentially any 32-bit value, making it impossible to prove the memory access is safe.

## Why the Error Message Focuses on R3

The error message mentions R3 because the verifier rejects the memory/length pair as a whole. When R4 is unbounded, the verifier cannot validate that `buffer` (14 bytes for `struct ethhdr`) is large enough for the requested `slice_len`. The "R3 and R4 memory, len pair leads to invalid memory access" indicates the pair is rejected due to the unbounded length.

## The Fix

The smallest fix is to use a **compile-time constant** for the length instead of a global variable. Since `slice_len` is initialized to `sizeof(struct ethhdr)` and never changed, we can just use `sizeof(*hdr)` or `sizeof(struct ethhdr)` directly in the call:

```c
#include <vmlinux.h>
#include <bpf/bpf_helpers.h>

char _license[] SEC("license") = "GPL";

struct {
	__uint(type, BPF_MAP_TYPE_RINGBUF);
	__uint(max_entries, 4096);
} ringbuf SEC(".maps");

SEC("?tc")
int entry(struct __sk_buff *skb)
{
	struct bpf_dynptr ptr;
	struct ethhdr *hdr;
	char buffer[sizeof(*hdr)] = {};

	bpf_dynptr_from_skb(skb, 0, &ptr);

	hdr = bpf_dynptr_slice(&ptr, 0, buffer, sizeof(*hdr));
	if (!hdr)
		return SK_DROP;

	return SK_PASS;
}
```

## Why This Works

By using `sizeof(*hdr)` directly:
1. The compiler evaluates this to a constant (14 bytes for `struct ethhdr`)
2. The BPF verifier can see this as an immediate constant value in the instruction
3. The verifier can verify that `buffer` (14 bytes on stack) is large enough for the requested slice length (14 bytes)
4. The memory/length pair becomes valid

The key insight is that eBPF verifiers require length arguments to helpers to be **verifier-trackable constants** (immediate values or values with known bounds), not arbitrary values loaded from memory or maps.
