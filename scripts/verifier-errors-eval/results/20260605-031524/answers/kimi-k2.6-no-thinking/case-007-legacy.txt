## Understanding the Failure

The verifier is rejecting the call to `bpf_dynptr_slice()` at instruction 16. Let's look at the error:

```
R4 unbounded memory access, use 'var &= const' or 'if (var < const)'
R3 and R4 memory, len pair leads to invalid memory access
```

**R4** contains `slice_len`, which is loaded from a map value at instructions 9-11:
```
11: (61) r4 = *(u32 *)(r1 +0)         ; R4=scalar(smin=0,smax=umax=0xffffffff,var_off=(0x0; 0xffffffff))
```

The problem is that `slice_len` is a global variable stored in a `.data` map. When loaded, the verifier sees it as an unbounded scalar (`smin=0,smax=umax=0xffffffff`). The `bpf_dynptr_slice()` helper requires the `len` parameter (R4) to have a known upper bound so it can verify that the memory access `buffer[0..len-1]` is safe.

The verifier needs to ensure that `len` doesn't exceed the size of `buffer` (which is `sizeof(struct ethhdr)` = 14 bytes). Since `slice_len` is loaded from memory as an arbitrary 32-bit value, the verifier cannot prove this is safe.

## Why This Happens

Even though `slice_len` is initialized to `sizeof(struct ethhdr)` at compile time, it's stored in a global data section (`.data` map). At verification time, the verifier treats map values as potentially modified by user space, so it sees an unbounded value.

The helper `bpf_dynptr_slice(&ptr, offset, buffer, len)` has this signature requirement: `len` must be bounded so the verifier can check that `buffer` is large enough.

## The Fix

The smallest fix is to use a compile-time constant directly instead of the global variable. We should pass `sizeof(struct ethhdr)` directly as the `len` argument, or use a local constant.

Here's the patch:

```c
#include <vmlinux.h>
#include <bpf/bpf_helpers.h>

char _license[] SEC("license") = "GPL";

struct {
	__uint(type, BPF_MAP_TYPE_RINGBUF);
	__uint(max_entries, 4096);
} ringbuf SEC(".maps");

__u32 slice_len = sizeof(struct ethhdr);

SEC("?tc")
int entry(struct __sk_buff *skb)
{
	struct bpf_dynptr ptr;
	struct ethhdr *hdr;
	char buffer[sizeof(*hdr)] = {};

	bpf_dynptr_from_skb(skb, 0, &ptr);

	hdr = bpf_dynptr_slice(&ptr, 0, buffer, sizeof(*hdr));
	if (!hdr)
		return SK_DROP;

	return SK_PASS;
}
```

The key change: replace `slice_len` with `sizeof(*hdr)` (or equivalently `sizeof(struct ethhdr)`) in the `bpf_dynptr_slice()` call.

## Why This Works

- `sizeof(*hdr)` is a compile-time constant (14 bytes for `struct ethhdr`)
- The verifier knows `buffer` is `sizeof(*hdr)` bytes (also 14 bytes)
- With a constant `len`, the verifier can trivially verify that `len <= sizeof(buffer)`
- The memory access is proven safe: we're reading at most 14 bytes into a 14-byte buffer

The `slice_len` global variable can remain in the program (it's harmless), but it's no longer used in a way that causes verification failure.
