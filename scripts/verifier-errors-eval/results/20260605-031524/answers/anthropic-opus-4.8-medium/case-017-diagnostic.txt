## Explanation

`bpf_local_irq_save`/`bpf_local_irq_restore` model IRQ-disabled critical sections that the verifier requires to be released in **last-in, first-out (LIFO)** order, just like a stack.

In the source:

```c
bpf_local_irq_save(&flags1);     // acquire id=1
bpf_local_irq_save(&flags2);     // acquire id=2  (innermost / most recent)
bpf_local_irq_restore(&flags1);  // tries to release id=1 first  <-- WRONG
bpf_local_irq_restore(&flags2);
```

The most recently saved flag is `flags2` (id=2), so it must be restored first. Restoring `flags1` first violates the nesting rule, producing:

```
cannot restore irq state out of order, expected id=2 acquired at insn_idx=7
```

## Fix

Swap the two restore calls so they unwind in reverse (LIFO) order:

```c
SEC("?tc")
int entry(struct __sk_buff *ctx)
{
	unsigned long flags1, flags2;

	bpf_local_irq_save(&flags1);
	bpf_local_irq_save(&flags2);
	bpf_local_irq_restore(&flags2);   /* restore innermost first */
	bpf_local_irq_restore(&flags1);
	return 0;
}
```

This matches the verifier's required reverse-order (LIFO) restore semantics and clears the "IRQ flag restore out of order" error.
