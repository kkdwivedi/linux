## Explanation

`bpf_dynptr_slice()` copies up to *len* bytes into the on‑stack `buffer` when the
requested region isn't contiguous in the dynptr. Its length argument is treated
by the verifier as an `ARG_CONST_SIZE`‑style bound: the verifier must be able to
prove that `len <= sizeof(buffer)`, otherwise the copy could overrun the stack
buffer.

Here the length comes from a **global variable** `slice_len`:

```
11: (61) r4 = *(u32 *)(r1 +0)   ; R4=scalar(... umax=0xffffffff ...)
```

Because the value is loaded from `.data` at runtime, the verifier only knows it
is some `u32` in `[0, 0xffffffff]`. It can't prove that value fits in the
16‑byte (`sizeof(struct ethhdr)`) stack buffer, hence:

```
R4 unbounded memory access, use 'var &= const' or 'if (var < const)'
R3 and R4 memory, len pair leads to invalid memory access
```

## Fix

Give the verifier a provable bound on the length. The smallest change is to
bound `slice_len` against the buffer size before the call (the message itself
suggests `if (var < const)` / `var &= const`):

```c
	if (slice_len > sizeof(buffer))
		return SK_DROP;

	hdr = bpf_dynptr_slice(&ptr, 0, buffer, slice_len);
```

After this branch the verifier knows `slice_len <= sizeof(buffer)` on the path
that reaches the call, so the `(R3, R4)` buffer/len pair is valid.

(Equivalently, if the intent is simply to read a full ethhdr, pass a constant:
`bpf_dynptr_slice(&ptr, 0, buffer, sizeof(buffer));` — that also satisfies the
constant‑size requirement. But if the test deliberately exercises a variable
length, the bound check above is the minimal targeted fix.)
