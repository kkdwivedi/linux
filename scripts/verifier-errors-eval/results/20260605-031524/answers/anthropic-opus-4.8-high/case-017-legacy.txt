## Explanation

The BPF verifier enforces that IRQ state (acquired via `bpf_local_irq_save`) must be released in **LIFO (stack) order** — the most recently saved IRQ flags must be restored first.

In the program:
- `flags1` is saved first (gets id=1, insn 3)
- `flags2` is saved second (gets id=2, insn 7)

But the restores happen in the *same* order they were saved:
- restore `flags1` (id=1) first
- restore `flags2` (id=2) second

When the verifier reaches the restore of `flags1` at insn 9, it expects the *last* acquired IRQ resource (id=2, from insn 7) to be released first. Since the program tries to restore id=1 instead, it fails:

```
cannot restore irq state out of order, expected id=2 acquired at insn_idx=7
```

## Fix

Swap the two restore calls so they unwind in LIFO order (restore `flags2` before `flags1`):

```c
SEC("?tc")
int entry(struct __sk_buff *ctx)
{
	unsigned long flags1, flags2;

	bpf_local_irq_save(&flags1);
	bpf_local_irq_save(&flags2);
	bpf_local_irq_restore(&flags2);   /* restore last-acquired first */
	bpf_local_irq_restore(&flags1);
	return 0;
}
```

This satisfies the verifier's nesting requirement: `flags2` (acquired last) is restored before `flags1` (acquired first), matching the expected LIFO ordering.
