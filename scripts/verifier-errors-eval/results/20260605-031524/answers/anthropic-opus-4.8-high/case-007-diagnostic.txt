## Explanation

`bpf_dynptr_slice()` takes a *buffer pointer / length* pair (R3 = `buffer`, R4 = `slice_len`). The helper may copy up to `len` bytes into `buffer`, so the verifier must be able to prove that `len` does not exceed the size of the object pointed to by `buffer`.

Here `buffer` is a 14-byte stack array (`char buffer[sizeof(*hdr)]`), but the length comes from a **global variable**:

```c
__u32 slice_len = sizeof(struct ethhdr);
```

A global like this is placed in the `.data` map. The verifier does not treat it as a compile-time constant — it loads it from the map as a fully unbounded `u32`:

```
11: (61) r4 = *(u32 *)(r1 +0)   ; R4=scalar(... var_off=(0x0; 0xffffffff))
```

So at the call site R4 can be anything up to `0xffffffff`, which is far larger than the 14-byte stack buffer. Hence:

```
R4 unbounded memory access, use 'var &= const' or 'if (var < const)'
R3 and R4 memory, len pair leads to invalid memory access
```

The verifier even tells you the fix: bound the variable before use.

## Fix

Add a bound check that ties `slice_len` to the actual buffer size before calling the helper:

```c
SEC("?tc")
int entry(struct __sk_buff *skb)
{
	struct bpf_dynptr ptr;
	struct ethhdr *hdr;
	char buffer[sizeof(*hdr)] = {};

	bpf_dynptr_from_skb(skb, 0, &ptr);

	if (slice_len > sizeof(buffer))      /* <-- added */
		return SK_DROP;

	hdr = bpf_dynptr_slice(&ptr, 0, buffer, slice_len);
	if (!hdr)
		return SK_DROP;

	return SK_PASS;
}
```

After the `if (slice_len > sizeof(buffer))` guard, the verifier knows on the fall-through path that `slice_len <= 14`, i.e. `R4` is bounded to the size of `buffer`, so the `(R3, R4)` memory/length pair is valid and the call type check passes.

(Equivalently `slice_len &= sizeof(buffer) - 1;` would also bound it, but only because `sizeof(buffer)` would need to be a power of two; the explicit `if (... > sizeof(buffer))` check is the clearer, generally-correct minimal fix.)
