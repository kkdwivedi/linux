## Explanation

The verifier enforces that nested IRQ-disabled regions created with `bpf_local_irq_save()` must be undone in **LIFO (last-in, first-out)** order. The code saves `flags1` then `flags2`, so `flags2` is the most recently acquired IRQ state and must be restored first.

The program instead restores `flags1` first:

```c
bpf_local_irq_save(&flags1);    // acquires id=1
bpf_local_irq_save(&flags2);    // acquires id=2  (active/top of stack)
bpf_local_irq_restore(&flags1); // tries to release id=1  <-- out of order
bpf_local_irq_restore(&flags2);
```

The verifier expects the next restore to release `id=2` (acquired at insn 7), but it sees a restore of `flags1` (id=1), hence:

```
cannot restore irq state out of order, expected id=2 acquired at insn_idx=7
```

## Fix

Swap the two restore calls so flags are released in reverse order of acquisition:

```c
SEC("?tc")
int entry(struct __sk_buff *ctx)
{
	unsigned long flags1, flags2;

	bpf_local_irq_save(&flags1);
	bpf_local_irq_save(&flags2);
	bpf_local_irq_restore(&flags2);
	bpf_local_irq_restore(&flags1);
	return 0;
}
```

This satisfies the LIFO requirement: `flags2` (last saved) is restored first, then `flags1`.
