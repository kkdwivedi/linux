## Explanation of the Verifier Failure

The verifier is rejecting this program because:

1. `bpf_local_irq_save(&flags)` at line 498 disables IRQs, entering an IRQ-disabled region
2. `helper_a(0)` at line 499 is a **sleepable global function** (marked `__noinline` without `__always_inline`)
3. Sleepable functions cannot be called in IRQ-disabled regions because they may call operations that sleep, which is unsafe when IRQs are disabled
4. `bpf_local_irq_restore(&flags)` at line 500 re-enables IRQs, but the call to `helper_a()` happens while still in the disabled region

The verifier tracks execution context safety and prevents this unsafe pattern.

## Proposed Fix

The smallest fix is to move the `helper_a(0)` call **outside** the IRQ-disabled critical section:

```c
SEC("?syscall")
int entry(void *ctx)
{
	unsigned long flags;

	helper_a(0);
	bpf_local_irq_save(&flags);
	bpf_local_irq_restore(&flags);
	return 0;
}
```

**Why this works:** By calling `helper_a(0)` before entering the IRQ-disabled region (before `bpf_local_irq_save`), the sleepable function is no longer constrained by the IRQ-disabled context, and the verifier allows it.

**Alternative (if the call must stay in the critical section):** Mark `helper_a` as non-sleepable by removing the `__noinline` attribute or making it `static __always_inline`, but this would require ensuring the function body doesn't call any sleepable helpers—which it does (`bpf_copy_from_user`), so this approach won't work here.

The first solution (moving the call outside) is the correct and minimal fix.
