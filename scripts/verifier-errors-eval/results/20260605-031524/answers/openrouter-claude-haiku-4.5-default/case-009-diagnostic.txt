## Explanation of the Verifier Failure

The verifier is rejecting the program because at line 42 in the main program:

```c
acquired = bpf_task_acquire(value->task);
```

The pointer `value->task` has type `rcu_ptr_or_null_task_struct`, meaning it **may be NULL**. However, `bpf_task_acquire()` is a kfunc that requires a **trusted, non-NULL pointer** as its first argument.

The issue occurs because:
1. `value` is checked for NULL (line 38: `if (!value)`)
2. But `value->task` is a kptr field that was stored in the map with `NULL` value initially (line 53: `local.task = NULL`)
3. Even though `bpf_kptr_xchg()` was called in `map_insert()`, the verifier cannot guarantee that the value returned from `bpf_map_lookup_elem()` in `helper_a()` has a non-NULL `task` field
4. The verifier sees `value->task` as `rcu_ptr_or_null_task_struct` and rejects the call

## The Fix

Add a NULL check on `value->task` before calling `bpf_task_acquire()`:

```c
SEC("tp_btf/task_newtask")
int BPF_PROG(entry, struct task_struct *task, u64 flags)
{
	struct task_struct *acquired;
	struct map_value *value;

	value = helper_a(task);
	if (!value)
		return 0;

	if (!value->task)
		return 0;

	acquired = bpf_task_acquire(value->task);
	if (!acquired)
		return 0;

	bpf_task_release(acquired);
	return 0;
}
```

**Why this works:** The added NULL check on `value->task` (line 11 in the fixed version) narrows the type from `rcu_ptr_or_null_task_struct` to `rcu_ptr_task_struct` (non-NULL), which satisfies the kfunc's requirement for a trusted, non-NULL pointer.
