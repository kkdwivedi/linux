## Explanation of the Verifier Failure

The verifier is rejecting the call to `bpf_dynptr_slice` because:

1. **Unbounded length (R4)**: The fourth argument `slice_len` is loaded from a global variable (`__u32 slice_len`), which the verifier treats as an unbounded scalar. The verifier cannot verify that this length is safe.

2. **Memory/length pair mismatch**: The third argument (R3, pointing to `buffer` on the stack at offset -32) and fourth argument (R4, the unbounded length) form a memory/length pair. The verifier requires that when you pass a stack pointer with a length, the length must be provably bounded by a constant or checked with an explicit bounds check.

3. **Stack memory safety**: The verifier cannot guarantee that accessing `buffer` with an unbounded length won't overflow the stack allocation.

## Root Cause

Using a global variable for the length defeats the verifier's ability to prove memory safety. The verifier needs to see a compile-time constant or an explicitly bounded value.

## Proposed Fix

Replace the global variable `slice_len` with a direct constant:

```c
#include <vmlinux.h>
#include <bpf/bpf_helpers.h>

char _license[] SEC("license") = "GPL";

struct {
	__uint(type, BPF_MAP_TYPE_RINGBUF);
	__uint(max_entries, 4096);
} ringbuf SEC(".maps");

SEC("?tc")
int entry(struct __sk_buff *skb)
{
	struct bpf_dynptr ptr;
	struct ethhdr *hdr;
	char buffer[sizeof(*hdr)] = {};

	bpf_dynptr_from_skb(skb, 0, &ptr);

	hdr = bpf_dynptr_slice(&ptr, 0, buffer, sizeof(*hdr));
	if (!hdr)
		return SK_DROP;

	return SK_PASS;
}
```

**Change**: Remove the global `__u32 slice_len` variable and replace `slice_len` with `sizeof(*hdr)` directly in the function call.

**Why this works**: `sizeof(*hdr)` is a compile-time constant that the verifier can reason about. It knows the exact bounds of the stack buffer and can verify that the memory access is safe.
