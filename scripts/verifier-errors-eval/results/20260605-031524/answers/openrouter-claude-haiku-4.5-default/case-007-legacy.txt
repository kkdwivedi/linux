## Verifier Failure Analysis

The verifier is rejecting the program because `slice_len` is a global variable with an unbounded value. When passed as the `size` argument to `bpf_dynptr_slice()`, the verifier cannot verify that the memory access is safe.

The specific error messages are:
1. **"R4 unbounded memory access"** - R4 contains the value of `slice_len`, which is a scalar with no upper bound constraints
2. **"R3 and R4 memory, len pair leads to invalid memory access"** - The combination of buffer pointer (R3) and unbounded length (R4) is unsafe

The problem is on line 11 where `slice_len` is loaded into R4:
```c
__u32 slice_len = sizeof(struct ethhdr);
```

Even though `slice_len` is initialized to `sizeof(struct ethhdr)`, it's a global variable that the verifier treats as potentially mutable and unbounded. The verifier requires that the size argument be either:
- A compile-time constant, or
- Bounded by an explicit runtime check (e.g., `if (slice_len < MAX)`)

## Solution

Replace the global variable with a compile-time constant:

```c
#define SLICE_LEN sizeof(struct ethhdr)
```

Then use it directly:
```c
hdr = bpf_dynptr_slice(&ptr, 0, buffer, SLICE_LEN);
```

## Complete Patch

```diff
 __u32 slice_len = sizeof(struct ethhdr);
+#define SLICE_LEN sizeof(struct ethhdr)
 
 SEC("?tc")
 int entry(struct __sk_buff *skb)
 {
 	struct bpf_dynptr ptr;
 	struct ethhdr *hdr;
 	char buffer[sizeof(*hdr)] = {};
 
 	bpf_dynptr_from_skb(skb, 0, &ptr);
 
-	hdr = bpf_dynptr_slice(&ptr, 0, buffer, slice_len);
+	hdr = bpf_dynptr_slice(&ptr, 0, buffer, SLICE_LEN);
 	if (!hdr)
 		return SK_DROP;
 
 	return SK_PASS;
 }
```

Alternatively, remove the global variable entirely and use the constant directly in the function call. The macro approach ensures the verifier sees a compile-time constant rather than a runtime-loaded value.
