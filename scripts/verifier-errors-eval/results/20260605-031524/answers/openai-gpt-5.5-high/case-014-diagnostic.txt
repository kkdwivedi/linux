The failure is caused by this sequence:

```asm
r3 = *(u32*)(r0 + 0);   /* r3 = value->offset, unconstrained u32 */
r1 += r3;              /* r1 = map_value + unknown offset */
...
call bpf_probe_read_kernel;
```

`map_a`’s value size is 48 bytes:

```c
struct value {
	__u32 offset;   /* 4 bytes */
	__u8 data[44]; /* 44 bytes */
};
```

The helper call uses:

```asm
r1 = destination pointer
r2 = size = 1
r3 = source pointer = 0
call bpf_probe_read_kernel
```

So the verifier must prove that `r1` points to at least 1 writable byte inside the map value. But `r1` is `map_value + value->offset`, and `value->offset` is loaded from the map as an unconstrained `u32`, with possible range `0..0xffffffff`. Therefore the verifier cannot prove that `offset + 1 <= 48`.

The smallest fix is to bounds-check the loaded offset before adding it to the map value pointer. Since the access size is 1 and the object size is 48, the valid maximum offset is `47`.

Patch:

```diff
diff --git a/case.c b/case.c
index 0000000..0000000 100644
--- a/case.c
+++ b/case.c
@@ -26,6 +26,7 @@ __naked void entry(void)
 	r1 = r0;					\
 	r3 = *(u32*)(r0 + 0);				\
+	if r3 > 47 goto l0_%=;				\
 	r1 += r3;					\
 	r2 = 1;						\
 	r3 = 0;						\
```

With that check, on the fallthrough path the verifier can infer:

```text
0 <= r3 <= 47
```

Then after:

```asm
r1 += r3
```

`r1` is known to be a pointer somewhere within the 48-byte map value, and the 1-byte write performed by `bpf_probe_read_kernel()` satisfies:

```text
offset + size <= 48
```

i.e.

```text
47 + 1 <= 48
```

So the helper destination pointer should pass verification.
