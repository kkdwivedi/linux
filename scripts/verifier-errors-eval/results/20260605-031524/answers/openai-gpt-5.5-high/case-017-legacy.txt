The verifier rejects this because `bpf_local_irq_save()` / `bpf_local_irq_restore()` are tracked like nested acquire/release operations.

From the log:

```text
call bpf_local_irq_save#62664         ; ... refs=1
call bpf_local_irq_save#62664         ; ... refs=1,2
...
call bpf_local_irq_restore#62663
cannot restore irq state out of order, expected id=2 acquired at insn_idx=7
```

The first `bpf_local_irq_save(&flags1)` creates tracked state/reference `id=1`.

The second `bpf_local_irq_save(&flags2)` creates tracked state/reference `id=2`.

The program then tries to restore `flags1` first:

```c
bpf_local_irq_restore(&flags1);
```

But the verifier expects the most recent save, `id=2`, to be restored first. In other words, nested irq saves must be restored in LIFO order.

Smallest fix: restore `flags2` before `flags1`.

Patch:

```diff
diff --git a/case.c b/case.c
index 0000000..0000000 100644
--- a/case.c
+++ b/case.c
@@ -8,8 +8,8 @@ int entry(struct __sk_buff *ctx)
 
 	bpf_local_irq_save(&flags1);
 	bpf_local_irq_save(&flags2);
-	bpf_local_irq_restore(&flags1);
 	bpf_local_irq_restore(&flags2);
+	bpf_local_irq_restore(&flags1);
 	return 0;
 }
```

Resulting program:

```c
#include <vmlinux.h>
#include <bpf/bpf_helpers.h>

SEC("?tc")
int entry(struct __sk_buff *ctx)
{
	unsigned long flags1, flags2;

	bpf_local_irq_save(&flags1);
	bpf_local_irq_save(&flags2);
	bpf_local_irq_restore(&flags2);
	bpf_local_irq_restore(&flags1);
	return 0;
}
```

This should satisfy the verifier because the irq state saved second is restored first, matching the tracked nesting order.
