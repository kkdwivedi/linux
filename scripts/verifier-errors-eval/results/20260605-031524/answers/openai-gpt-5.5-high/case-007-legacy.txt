The failure is at the `bpf_dynptr_slice()` call:

```c
hdr = bpf_dynptr_slice(&ptr, 0, buffer, slice_len);
```

`buffer` is a 14-byte stack object (`sizeof(struct ethhdr)`). But `slice_len` is a non-const global variable, so it lives in the BPF `.data` map. The verifier does **not** treat its initializer as a trusted constant; it sees the load as an arbitrary `u32`:

```text
R4=scalar(smin=0,smax=umax=0xffffffff)
```

So at the helper call, the verifier sees:

- `R3 = fp-32`: pointer to a 14-byte stack buffer
- `R4 = unknown u32`: possible length up to `0xffffffff`

That could make the helper access past the end of `buffer`, so verification fails:

```text
R4 unbounded memory access
R3 and R4 memory, len pair leads to invalid memory access
```

Smallest clear fix: pass a compile-time bounded size instead of the mutable global.

```diff
--- a/case.c
+++ b/case.c
@@ -19,7 +19,7 @@ int entry(struct __sk_buff *skb)
 
 	bpf_dynptr_from_skb(skb, 0, &ptr);
 
-	hdr = bpf_dynptr_slice(&ptr, 0, buffer, slice_len);
+	hdr = bpf_dynptr_slice(&ptr, 0, buffer, sizeof(buffer));
 	if (!hdr)
 		return SK_DROP;
```

With this, the verifier should see the fourth argument as constant `14`, matching the stack buffer size, so the helper memory/length pair is safe.

If `slice_len` must remain mutable, then load it into a local and bound it before the helper call:

```c
__u32 len;

bpf_dynptr_from_skb(skb, 0, &ptr);

len = slice_len;
if (len > sizeof(buffer))
	return SK_DROP;

hdr = bpf_dynptr_slice(&ptr, 0, buffer, len);
```

But if the intended length is always `sizeof(struct ethhdr)`, using `sizeof(buffer)` directly is the smallest fix.
