The verifier failure is because `bpf_local_irq_save()` / `bpf_local_irq_restore()` are tracked as a scoped resource, and nested IRQ-save regions must be unwound in last-in, first-out order.

Current order:

```c
bpf_local_irq_save(&flags1);     // acquire id=1
bpf_local_irq_save(&flags2);     // acquire id=2

bpf_local_irq_restore(&flags1);  // tries to restore id=1 while id=2 is still active
bpf_local_irq_restore(&flags2);
```

At the first restore, the verifier expects the most recently saved IRQ state, `flags2`, but the program restores `flags1`, so it rejects the program:

```text
cannot restore irq state out of order, expected id=2 acquired at insn_idx=7
```

The smallest fix is to restore in reverse order:

```diff
diff --git a/case.c b/case.c
index 0000000..1111111 100644
--- a/case.c
+++ b/case.c
@@ -8,8 +8,8 @@ int entry(struct __sk_buff *ctx)
 
 	bpf_local_irq_save(&flags1);
 	bpf_local_irq_save(&flags2);
-	bpf_local_irq_restore(&flags1);
 	bpf_local_irq_restore(&flags2);
+	bpf_local_irq_restore(&flags1);
 	return 0;
 }
```

Resulting program:

```c
SEC("?tc")
int entry(struct __sk_buff *ctx)
{
	unsigned long flags1, flags2;

	bpf_local_irq_save(&flags1);
	bpf_local_irq_save(&flags2);
	bpf_local_irq_restore(&flags2);
	bpf_local_irq_restore(&flags1);
	return 0;
}
```

This satisfies the verifier because the IRQ-disabled regions are restored in LIFO order: save `flags1`, save `flags2`, restore `flags2`, restore `flags1`.
