The verifier is rejecting the program because `ptr2` is reserved but not released on the successful path.

After these two calls:

```c
bpf_ringbuf_reserve_dynptr(&ringbuf, sizeof(*sample), 0, &ptr1);
bpf_ringbuf_reserve_dynptr(&ringbuf, sizeof(*sample), 0, &ptr2);
```

the verifier tracks two outstanding ringbuf references:

```text
refs=1,3
```

On the `!sample` path, both are discarded, so that path is fine:

```c
bpf_ringbuf_discard_dynptr(&ptr1, 0);
bpf_ringbuf_discard_dynptr(&ptr2, 0);
```

But on the success path, only `ptr1` is submitted:

```c
bpf_ringbuf_submit_dynptr(&ptr1, 0);
return 0;
```

That releases reference `id=1`, but `ptr2`’s reference `id=3` is still live at program exit:

```text
32: call bpf_ringbuf_submit_dynptr#199   ; refs=3
34: exit
Unreleased reference id=3 alloc_insn=14
BPF_EXIT instruction in main prog would lead to reference leak
```

Every ringbuf dynptr reserved with `bpf_ringbuf_reserve_dynptr()` must be either submitted or discarded on every exit path.

Smallest likely fix: discard `ptr2` on the success path as well.

Patch:

```diff
diff --git a/case.c b/case.c
index 0000000..0000000 100644
--- a/case.c
+++ b/case.c
@@ -25,6 +25,7 @@ int entry(void *ctx)
 	}
 
 	bpf_ringbuf_submit_dynptr(&ptr1, 0);
+	bpf_ringbuf_discard_dynptr(&ptr2, 0);
 
 	return 0;
 }
```

Equivalently, discarding `ptr2` before submitting `ptr1` should also satisfy the verifier:

```c
bpf_ringbuf_discard_dynptr(&ptr2, 0);
bpf_ringbuf_submit_dynptr(&ptr1, 0);
```

The important part is that both `ptr1` and `ptr2` are released on the non-NULL `sample` path.
