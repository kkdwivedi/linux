The verifier rejects this before normal instruction/range analysis because the subprogram call graph contains a direct cycle:

```text
entry -> helper_a
helper_a -> helper_a
```

Even though the source appears to bound the recursion with:

```asm
r1 += 1;
if r1 < 4 goto l0;
```

the verifier does not allow recursive bpf-to-bpf calls at all. It requires the subprogram call graph to be acyclic so stack depth and analysis remain bounded.

The smallest source-level fix is to rewrite the self-call as an explicit bounded loop inside `helper_a`. The logic is equivalent for the current program: starting with `r1 = 0`, increment `r1` until it reaches `4`, then return.
