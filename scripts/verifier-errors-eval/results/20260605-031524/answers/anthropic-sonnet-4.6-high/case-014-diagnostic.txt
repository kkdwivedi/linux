## Explanation of the Failure

The verifier rejects the program at the `bpf_probe_read_kernel` call because `r1` (the destination buffer) has an **unbounded** offset into the map value:

1. `r3 = *(u32*)(r0 + 0)` loads the `offset` field — the verifier tracks it as a 32-bit scalar with range `[0, 0xffffffff]`.
2. `r1 += r3` makes `r1` a map-value pointer with an **unknown** offset anywhere in `[0, 4294967295]`.
3. `bpf_probe_read_kernel` with `r2=1` needs the verifier to prove `(offset of r1) + 1 ≤ 48` (the value size), but it cannot.

## Fix

Add a bounds check on `r3` **before** adding it to `r1`. The map value is 48 bytes, and the access size is 1 byte, so we need `r3 < 48`. Jumping to the exit label when `r3 ≥ 48` constrains the fall-through path to `r3 ∈ [0, 47]`, satisfying `offset + 1 ≤ 48`.

```diff
 	r1 = r0;					\
 	r3 = *(u32*)(r0 + 0);				\
+	if r3 >= 48 goto l0_%=;				\
 	r1 += r3;					\
```

### Complete fixed program

```c
SEC("tracepoint")
__naked void entry(void)
{
	asm volatile ("					\
	r2 = r10;					\
	r2 += -8;					\
	r1 = 0;						\
	*(u64*)(r2 + 0) = r1;				\
	r1 = %[map_a] ll;				\
	call %[bpf_map_lookup_elem];			\
	if r0 == 0 goto l0_%=;				\
	r1 = r0;					\
	r3 = *(u32*)(r0 + 0);				\
	if r3 >= 48 goto l0_%=;				\
	r1 += r3;					\
	r2 = 1;						\
	r3 = 0;						\
	call %[bpf_probe_read_kernel];			\
l0_%=:	exit;						\
"	:
	: __imm(bpf_map_lookup_elem),
	  __imm(bpf_probe_read_kernel),
	  __imm_addr(map_a)
	: __clobber_all);
}
```

After the `if r3 >= 48 goto l0_%=` check, the verifier knows `r3 ∈ [0, 47]`, so `r1 = map_value + r3` has its maximum byte access at offset `47 + 1 = 48 ≤ 48` (the value size), and the bounds check passes.
