## Explanation of the Failure

At instruction 9, the code loads a 32-bit value from the map value (`r3 = *(u32*)(r0 + 0)`) — the `offset` field of `struct value`. The verifier tracks this as:

```
R3=scalar(smin=0,smax=umax=0xffffffff,var_off=(0x0; 0xffffffff))
```

At instruction 10, `r1 += r3` makes `r1` a `map_value` pointer with an **unbounded** variable offset (0 to 4 GB). The verifier cannot prove that `r1 + 1` stays within the 48-byte map value, so it rejects the call to `bpf_probe_read_kernel` at instruction 13:

```
R1 unbounded memory access, make sure to bounds check any such access
```

## Fix

Insert a bounds check on `r3` **before** adding it to `r1`. The map value is 48 bytes (`vs=48`). For a 1-byte write (`r2=1`) at `r1 = map_value + r3`, we need `r3 + 1 ≤ 48`, i.e., `r3 ≤ 47`. A conditional branch accomplishes this:

```c
SEC("tracepoint")
__naked void entry(void)
{
	asm volatile ("					\
	r2 = r10;					\
	r2 += -8;					\
	r1 = 0;						\
	*(u64*)(r2 + 0) = r1;				\
	r1 = %[map_a] ll;				\
	call %[bpf_map_lookup_elem];			\
	if r0 == 0 goto l0_%=;				\
	r1 = r0;					\
	r3 = *(u32*)(r0 + 0);				\
	if r3 > 47 goto l0_%=;				\
	r1 += r3;					\
	r2 = 1;						\
	r3 = 0;						\
	call %[bpf_probe_read_kernel];			\
l0_%=:	exit;						\
"	:
	: __imm(bpf_map_lookup_elem),
	  __imm(bpf_probe_read_kernel),
	  __imm_addr(map_a)
	: __clobber_all);
}
```

The added line `if r3 > 47 goto l0_%=;` constrains `r3` to `[0, 47]` in the fall-through path. The verifier can then confirm that `r1 = map_value + r3` with `r3 ∈ [0, 47]` and a 1-byte access stays entirely within the 48-byte map value, satisfying the bounds check.
