## Root Cause

The verifier enforces **LIFO (last-in, first-out) ordering** for `bpf_res_spin_lock`/`bpf_res_spin_unlock` pairs. Locks must be released in the reverse of acquisition order.

In the original code:
```c
bpf_res_spin_lock(&lock_a);   // acquired 1st
bpf_res_spin_lock(&lock_b);   // acquired 2nd
...
bpf_res_spin_unlock(&lock_a); // released 1st ← WRONG ORDER
bpf_res_spin_unlock(&lock_b); // released 2nd
```

The compiler also merges the two `bpf_res_spin_unlock(&lock_a)` calls (from the failure branch and the success path) into a single unlock of `lock_a` that runs unconditionally right after `lock_b`'s call — before `lock_b` is unlocked. The verifier catches this as out-of-order:

```
10: call bpf_res_spin_unlock  ← unlocks lock_a while lock_b is still held
bpf_res_spin_unlock cannot be out of order
```

## Fix

Swap the two unlock calls at the end so they follow LIFO order (unlock `lock_b` first, since it was acquired last):

```diff
-	bpf_res_spin_unlock(&lock_a);
 	bpf_res_spin_unlock(&lock_b);
+	bpf_res_spin_unlock(&lock_a);
 	return 0;
```

### Fixed source:
```c
SEC("?tc")
int entry(struct __sk_buff *ctx)
{
	if (bpf_res_spin_lock(&lock_a))
		return 0;
	if (bpf_res_spin_lock(&lock_b)) {
		bpf_res_spin_unlock(&lock_a);
		return 0;
	}
	bpf_res_spin_unlock(&lock_b);  // release last-acquired first
	bpf_res_spin_unlock(&lock_a);  // then release first-acquired
	return 0;
}
```

This satisfies the verifier's LIFO requirement: `lock_b` (acquired second) is always released before `lock_a` (acquired first) in any path where both are held.
