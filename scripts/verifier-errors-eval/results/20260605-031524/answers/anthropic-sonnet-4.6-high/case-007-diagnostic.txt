## Root Cause

The verifier rejects the call because `slice_len` is a **global variable** (`__u32 slice_len = sizeof(struct ethhdr)`). When loaded at runtime (insn 11), R4 becomes an unbounded scalar — the verifier has no way to prove it fits within the stack buffer pointed to by R3. The verifier requires the length to be a bounded/known value when pairing it with a stack pointer.

```
R4 unbounded memory access, use 'var &= const' or 'if (var < const)'
R3 and R4 memory, len pair leads to invalid memory access
```

## Fix

Replace the runtime variable `slice_len` with the compile-time constant `sizeof(*hdr)` (equivalently `sizeof(struct ethhdr)`) directly in the `bpf_dynptr_slice` call. This gives the verifier a concrete, bounded size that it can verify fits within the `buffer` array.

```diff
-	hdr = bpf_dynptr_slice(&ptr, 0, buffer, slice_len);
+	hdr = bpf_dynptr_slice(&ptr, 0, buffer, sizeof(*hdr));
```

With `sizeof(*hdr)` as a compile-time constant, the verifier can confirm that the length equals `sizeof(struct ethhdr)` — exactly the size of `buffer` — so the memory/length pair is valid and verification succeeds.
