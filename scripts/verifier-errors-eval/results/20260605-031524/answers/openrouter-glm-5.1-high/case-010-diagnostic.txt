## Explanation

The verifier failure is caused by `skb + 1` in `helper_b`:

```c
return helper_a(skb) + helper_c(val, skb + 1);
```

In C, pointer arithmetic `skb + 1` advances the pointer by `sizeof(struct __sk_buff)` (192 bytes on this platform). The BPF verifier tracks that `R2` is a context pointer (`ctx()`) with an offset of 192. When `helper_c` then tries to dereference this pointer (accessing `skb->ifindex`), the verifier rejects it because **context pointers must be used in their original, unmodified form** — you cannot pass an offset-adjusted ctx pointer to a subprogram.

The log confirms this:
- Instruction 21: `r6 += 192` — the `skb + 1` pointer arithmetic
- Instruction 23: `r2 = r6` — passing the modified ctx pointer as arg2
- Instruction 24: `call pc+2` — calling `helper_c` with the invalid pointer
- Error: *"dereference of modified ctx ptr R2 off=192 disallowed"*

## Fix

The `skb + 1` is almost certainly a bug — `helper_c` expects a valid `struct __sk_buff *`, not a pointer past the end of the context object. The smallest fix is to pass `skb` directly:

```c
return helper_a(skb) + helper_c(val, skb);
```

That is, change line 19 from:
```c
		return helper_a(skb) + helper_c(val, skb + 1);
```
to:
```c
		return helper_a(skb) + helper_c(val, skb);
```

This preserves the original (unmodified) context pointer when passing it to `helper_c`, which is what the verifier requires.
