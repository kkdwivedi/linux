## Verifier Failure Explanation

The verifier rejects the program at line 42:

```c
acquired = bpf_task_acquire(value->task);
```

The issue is that `value->task` is a kptr field read from a map value. The verifier tracks its type as `rcu_ptr_or_null_task_struct` — meaning it **may be NULL**. However, `bpf_task_acquire` requires a **non-NULL** trusted pointer to `struct task_struct`.

Even though `map_insert` stores a non-NULL task pointer via `bpf_kptr_xchg`, the verifier cannot guarantee that `value->task` is non-NULL when read back from the map (another path could have set it to NULL, or the kptr could have been swapped out). The code checks that `value` itself is non-NULL, but never checks that `value->task` is non-NULL before passing it to `bpf_task_acquire`.

## Fix

Add a NULL check for `value->task` before calling `bpf_task_acquire`:

```c
SEC("tp_btf/task_newtask")
int BPF_PROG(entry, struct task_struct *task, u64 flags)
{
	struct task_struct *acquired;
	struct map_value *value;

	value = helper_a(task);
	if (!value)
		return 0;

	if (!value->task)
		return 0;

	acquired = bpf_task_acquire(value->task);
	if (!acquired)
		return 0;

	bpf_task_release(acquired);
	return 0;
}
```

The two added lines (`if (!value->task) return 0;`) ensure that on the path where `bpf_task_acquire` is called, the verifier knows `value->task` is non-NULL, satisfying the kfunc's contract. This is the minimal fix — it adds exactly the NULL check the verifier's suggestion recommends.
