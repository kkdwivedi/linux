## Verifier Failure Explanation

The failure occurs at the `bpf_task_acquire(value->task)` call in the `entry` function:

```
3: (79) r1 = *(u64 *)(r0 +0)    ; R1=rcu_ptr_or_null_task_struct(id=10)
4: (85) call bpf_task_acquire#63762
Possibly NULL pointer passed to trusted R1
```

When reading `value->task` (a kptr stored in the map), the verifier types it as `rcu_ptr_or_null_task_struct` — meaning it **could be NULL**. The `bpf_task_acquire` kfunc requires a **trusted, non-NULL** pointer as its argument. Since the verifier cannot prove `value->task` is non-NULL, it rejects the call.

This makes sense: even though `map_insert` stores a non-NULL task pointer via `bpf_kptr_xchg`, the verifier doesn't track that across function calls. When `entry` reads the kptr back from the map, it must account for the possibility that the field was never populated (or was cleared).

## Fix

Add a NULL check on `value->task` before passing it to `bpf_task_acquire`:

```c
SEC("tp_btf/task_newtask")
int BPF_PROG(entry, struct task_struct *task, u64 flags)
{
	struct task_struct *acquired;
	struct map_value *value;

	value = helper_a(task);
	if (!value)
		return 0;

	if (!value->task)       // <-- add this NULL check
		return 0;

	acquired = bpf_task_acquire(value->task);
	if (!acquired)
		return 0;

	bpf_task_release(acquired);
	return 0;
}
```

After the NULL check, the verifier will narrow the type from `rcu_ptr_or_null_task_struct` to `rcu_ptr_task_struct` (non-NULL), which satisfies the `trusted` argument requirement of `bpf_task_acquire`.
