## Explanation of the Failure

The verifier rejects the call because `slice_len` is a global variable loaded from a map value at runtime. At instruction 11, the verifier assigns R4 a completely unbounded scalar range (`smin=0, smax=0xffffffff`). When `bpf_dynptr_slice` is called with R3 (the stack buffer) and R4 (the length) as a memory/length pair, the verifier cannot prove the stack buffer is large enough for the requested length — R4 could be anything up to 4 GB, while the buffer is only `sizeof(struct ethhdr)` bytes.

The core rule: for the `buffer`/`buffer_sz` pair in `bpf_dynptr_slice`, the length must be a compile-time constant (or otherwise bounded) so the verifier can confirm the stack allocation covers it.

## Fix

Replace the runtime variable `slice_len` with the compile-time constant `sizeof(buffer)` (equivalently `sizeof(*hdr)`):

```diff
-	hdr = bpf_dynptr_slice(&ptr, 0, buffer, slice_len);
+	hdr = bpf_dynptr_slice(&ptr, 0, buffer, sizeof(buffer));
```

With a compile-time constant length the verifier can statically verify that `buffer` (allocated on the stack as `char buffer[sizeof(*hdr)]`) is exactly as large as the requested slice, satisfying the memory/length pair contract.

### Complete fixed `entry` function

```c
SEC("?tc")
int entry(struct __sk_buff *skb)
{
	struct bpf_dynptr ptr;
	struct ethhdr *hdr;
	char buffer[sizeof(*hdr)] = {};

	bpf_dynptr_from_skb(skb, 0, &ptr);

	hdr = bpf_dynptr_slice(&ptr, 0, buffer, sizeof(buffer));
	if (!hdr)
		return SK_DROP;

	return SK_PASS;
}
```
