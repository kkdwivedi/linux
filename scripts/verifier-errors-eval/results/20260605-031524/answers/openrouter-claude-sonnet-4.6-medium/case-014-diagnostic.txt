## Explanation of the Failure

The verifier rejects the program at the `bpf_probe_read_kernel` call because `r1` (the destination pointer) is a `map_value` pointer with an **unbounded variable offset**.

The sequence is:
1. `r1 = r0` — r1 points to the start of the 48-byte map value
2. `r3 = *(u32*)(r0 + 0)` — r3 gets the `offset` field; the verifier only knows it's a `u32`, so its range is `[0, 4294967295]`
3. `r1 += r3` — r1 now has a completely unbounded variable offset into the map value

The verifier needs to prove that `r1 + size ≤ map_value_end` (i.e., `offset + 1 ≤ 48`), but without a bounds check on `r3`, it cannot.

## Fix

Add a bounds check on `r3` before adding it to `r1`. Since the map value is 48 bytes and we read 1 byte, we need `r3 ≤ 47` (i.e., `r3 < 48`):

```diff
 	r1 = r0;					\
 	r3 = *(u32*)(r0 + 0);				\
+	if r3 >= 48 goto l0_%=;				\
 	r1 += r3;					\
 	r2 = 1;						\
```

After the conditional branch, the verifier knows `0 ≤ r3 ≤ 47`, so `r1 + r3` stays within the 48-byte map value, and access of 1 byte is safe (`offset + 1 ≤ 48`).

### Full patched inline asm:

```c
asm volatile ("					\
r2 = r10;					\
r2 += -8;					\
r1 = 0;						\
*(u64*)(r2 + 0) = r1;				\
r1 = %[map_a] ll;				\
call %[bpf_map_lookup_elem];			\
if r0 == 0 goto l0_%=;				\
r1 = r0;					\
r3 = *(u32*)(r0 + 0);				\
if r3 >= 48 goto l0_%=;				\
r1 += r3;					\
r2 = 1;						\
r3 = 0;						\
call %[bpf_probe_read_kernel];			\
l0_%=:	exit;					\
"	:
: __imm(bpf_map_lookup_elem),
  __imm(bpf_probe_read_kernel),
  __imm_addr(map_a)
: __clobber_all);
```
