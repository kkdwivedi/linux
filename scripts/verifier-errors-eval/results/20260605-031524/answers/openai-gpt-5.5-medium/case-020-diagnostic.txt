The program is verifier-pathological: every function contains 50 BPF-to-BPF calls to the next helper, and the call chain is deep:

```text
entry -> helper_a -> helper_b -> helper_c -> helper_d -> helper_e -> helper_f -> helper_g
```

Each call also passes a different stack pointer value in `r1`:

```asm
r1 = r10;
r1 += -off;
call helper_x;
```

So the verifier’s subprogram liveness analysis ends up recomputing liveness for the same lower subprograms through many distinct call paths / argument states. By the time it repeatedly reaches `helper_g`, it exceeds the verifier’s liveness-complexity cap:

```text
liveness analysis exceeded complexity limit (10001 calls)
```

This is not an instruction-count failure; it happens before normal state exploration:

```text
processed 0 insns ...
```

### Smallest likely source-level fix

Make the helper subprograms global instead of `static`.

For BPF, non-static/global subprograms are verified more like independent global functions instead of being context-sensitively re-analyzed through every caller path. Since these helpers take no declared arguments and ignore `r1`, making them global should avoid the exponential liveness recomputation while preserving the actual instruction structure.
