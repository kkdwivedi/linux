The failure is caused by the 4th argument to `bpf_dynptr_slice()`:

```c
hdr = bpf_dynptr_slice(&ptr, 0, buffer, slice_len);
```

`buffer` is a stack object of size `sizeof(struct ethhdr)`, i.e. 14 bytes. But `slice_len` is a non-const global:

```c
__u32 slice_len = sizeof(struct ethhdr);
```

Even though it is initialized to 14, the verifier treats non-const globals as mutable map data. Therefore, at verification time, the load of `slice_len` is considered an arbitrary `u32`:

```text
R4=scalar(smin=0,smax=umax=0xffffffff)
```

`bpf_dynptr_slice()` takes a memory/length pair for the fallback buffer: arg3 is the buffer pointer and arg4 is the buffer length. The verifier must prove that `buffer` is valid for `slice_len` bytes. Since `slice_len` may be as large as `0xffffffff`, it cannot prove that the 14-byte stack buffer is large enough:

```text
R4 unbounded memory access, use 'var &= const' or 'if (var < const)'
R3 and R4 memory, len pair leads to invalid memory access
```

The smallest fix is to pass a verifier-known bounded length, e.g. `sizeof(buffer)`, instead of the mutable global.

Patch:

```diff
diff --git a/case.c b/case.c
index 0000000..0000000 100644
--- a/case.c
+++ b/case.c
@@ -19,7 +19,7 @@ int entry(struct __sk_buff *skb)
 
 	bpf_dynptr_from_skb(skb, 0, &ptr);
 
-	hdr = bpf_dynptr_slice(&ptr, 0, buffer, slice_len);
+	hdr = bpf_dynptr_slice(&ptr, 0, buffer, sizeof(buffer));
 	if (!hdr)
 		return SK_DROP;
 
```

With this change, the verifier sees the length as the constant size of the stack buffer, so the memory/length pair is valid.

If `slice_len` must remain runtime-configurable, then bound it before the helper call instead:

```c
__u32 len = slice_len;

if (len > sizeof(buffer))
	return SK_DROP;

hdr = bpf_dynptr_slice(&ptr, 0, buffer, len);
```

But for the given program, replacing `slice_len` with `sizeof(buffer)` is the minimal source-level repair.
