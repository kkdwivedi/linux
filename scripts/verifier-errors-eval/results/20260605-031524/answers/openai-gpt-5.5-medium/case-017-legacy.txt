The verifier failure is due to the order of `bpf_local_irq_restore()` calls.

`bpf_local_irq_save(&flags1)` creates an IRQ-state “reference” with id `1`.  
`bpf_local_irq_save(&flags2)` creates another one with id `2`.

The verifier requires these stateful resources to be restored in LIFO order, like a stack:

```text
save flags1   -> id 1
save flags2   -> id 2
restore flags2
restore flags1
```

But the program currently does:

```c
bpf_local_irq_restore(&flags1);
bpf_local_irq_restore(&flags2);
```

So at instruction 9, it tries to restore id `1` while id `2` is still the most recent outstanding IRQ state. That is why the verifier reports:

```text
cannot restore irq state out of order, expected id=2 acquired at insn_idx=7
```

Smallest fix: restore `flags2` before `flags1`.

Patch:

```diff
diff --git a/case.c b/case.c
index 0000000..0000000 100644
--- a/case.c
+++ b/case.c
@@ -8,8 +8,8 @@ int entry(struct __sk_buff *ctx)
 
 	bpf_local_irq_save(&flags1);
 	bpf_local_irq_save(&flags2);
-	bpf_local_irq_restore(&flags1);
 	bpf_local_irq_restore(&flags2);
+	bpf_local_irq_restore(&flags1);
 	return 0;
 }
```

Fixed source:

```c
#include <vmlinux.h>
#include <bpf/bpf_helpers.h>

SEC("?tc")
int entry(struct __sk_buff *ctx)
{
	unsigned long flags1, flags2;

	bpf_local_irq_save(&flags1);
	bpf_local_irq_save(&flags2);
	bpf_local_irq_restore(&flags2);
	bpf_local_irq_restore(&flags1);
	return 0;
}
```

This should satisfy the verifier because the IRQ state references are released in the reverse order in which they were acquired.
