**Explanation**

The verifier rejects the program because it cannot prove that the destination pointer passed to `bpf_probe_read_kernel` stays inside the 48-byte map value.

The sequence

```asm
r3 = *(u32*)(r0 + 0)
r1 += r3
```

loads an arbitrary `u32` from the map value into `r3` and adds it to the map value pointer `r1`. The verifier therefore sees `r1` as a `map_value` pointer with a variable offset in the full unsigned 32-bit range `[0, 4294967295]`. When `bpf_probe_read_kernel` tries to write 1 byte at `r1`, the verifier requires `offset + 1 <= 48`, which is impossible to prove.

The fix is to bound `r3` before adding it to `r1`. Since the object is 48 bytes and the write size is 1 byte, the offset must be at most `47`. Adding an unsigned range check `if r3 > 47 goto l0_%=;` tells the verifier that on the fall-through path `r3` is in `[0, 47]`, so `r1 + r3` always points at least 1 byte inside the object.

**Patch**

```diff
 	r3 = *(u32*)(r0 + 0);				\
+	if r3 > 47 goto l0_%=;				\
 	r1 += r3;					\
```

With this check, `r1`’s variable offset is capped at 47, making the subsequent `bpf_probe_read_kernel` call satisfy `offset + 1 <= 48`.
