**Explanation**

The verifier fails because `slice_len` is a global variable. In BPF, global variables live in maps, so at verification time the value is loaded from map memory and treated as an arbitrary 32‑bit scalar (`0 … 0xffffffff`).  

`bpf_dynptr_slice` checks that the supplied stack buffer is at least `len` bytes large. Because the verifier cannot prove that the unbounded map value `slice_len` fits inside the on‑stack `buffer` (which is only `sizeof(struct ethhdr)` bytes), it rejects the program with:

```
R4 unbounded memory access
R3 and R4 memory, len pair leads to invalid memory access
```

**Fix**

Pass a compile‑time constant for the length argument so the verifier can see the exact buffer size. Replacing `slice_len` with `sizeof(*hdr)` (or `sizeof(buffer)`) makes the length a known constant that matches the declaration of `buffer`.

```diff
--- a/case.c
+++ b/case.c
@@ -21,7 +21,7 @@ int entry(struct __sk_buff *skb)
 
 	bpf_dynptr_from_skb(skb, 0, &ptr);
 
-	hdr = bpf_dynptr_slice(&ptr, 0, buffer, slice_len);
+	hdr = bpf_dynptr_slice(&ptr, 0, buffer, sizeof(*hdr));
 	if (!hdr)
 		return SK_DROP;
```

This is the smallest change needed: the global `slice_len` variable can remain (it simply becomes unused), but the helper call now receives a bounded constant that the verifier can relate directly to the stack allocation.
