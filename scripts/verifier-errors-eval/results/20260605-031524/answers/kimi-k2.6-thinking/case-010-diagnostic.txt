**Explanation**

In BPF, the `struct __sk_buff *` context pointer is a special pointer type (`PTR_TO_CTX`).  
The verifier tracks its offset and does **not** allow passing a context pointer that has been
modified by arithmetic to another function that expects the original context type.

In `helper_b()` the expression `skb + 1` adds `sizeof(struct __sk_buff)` (192 bytes) to the
pointer. The resulting register is still a `PTR_TO_CTX`, but with offset `192`. When that
modified pointer is passed to `helper_c()`, the verifier rejects it:

```
dereference of modified ctx ptr R2 off=192 disallowed
```

The program only ever needs the original, unmodified `skb` pointer, so the arithmetic is
unnecessary and unsafe.

**Fix**

Pass the unmodified `skb` pointer to `helper_c`.

**Patch**

```diff
--- a/case.c
+++ b/case.c
@@ -17,7 +17,7 @@ int helper_c(int val, struct __sk_buff *skb);
 __attribute__((noinline))
 int helper_b(int val, struct __sk_buff *skb)
 {
-	return helper_a(skb) + helper_c(val, skb + 1);
+	return helper_a(skb) + helper_c(val, skb);
 }
```

With this change `helper_b` retains the original `PTR_TO_CTX` (offset 0) for both calls,
so the verifier will accept the argument passed to `helper_c` and the program will pass
verification.
