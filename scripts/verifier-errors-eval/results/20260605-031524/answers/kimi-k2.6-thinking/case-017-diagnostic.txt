**Explanation**

The eBPF verifier enforces strict LIFO (last-in, first-out) nesting for IRQ-disabled regions created by `bpf_local_irq_save()` / `bpf_local_irq_restore()`.  
In the source, the save order is:

1. `flags1`
2. `flags2`

But the restore order is:

1. `flags1`  ← **wrong**
2. `flags2`

Because `flags2` was saved most recently, the verifier expects it to be restored first. Restoring `flags1` first breaks the nesting stack, so the verifier rejects the program with *“IRQ flag restore out of order”*.

**Fix**

Swap the two restore calls so they run in reverse save order:

```c
bpf_local_irq_restore(&flags2);
bpf_local_irq_restore(&flags1);
```

**Complete patch**

```diff
--- a/case.c
+++ b/case.c
@@ -245,8 +245,8 @@ int entry(struct __sk_buff *ctx)
 
 	bpf_local_irq_save(&flags1);
 	bpf_local_irq_save(&flags2);
-	bpf_local_irq_restore(&flags1);
 	bpf_local_irq_restore(&flags2);
+	bpf_local_irq_restore(&flags1);
 	return 0;
 }
```
