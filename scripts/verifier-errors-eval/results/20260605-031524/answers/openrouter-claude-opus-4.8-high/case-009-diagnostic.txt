## Explanation

The failure is at `case.c:42`:

```c
acquired = bpf_task_acquire(value->task);
```

`value->task` is a kptr stored in the map. When the verifier loads it, it produces an `rcu_ptr_or_null_task_struct` — i.e. a pointer that **may be NULL**. `bpf_task_acquire()` is a kfunc whose first argument must be a *non-NULL* trusted `struct task_struct *`. Because the loaded pointer is potentially NULL and you pass it directly to the kfunc, the verifier rejects the call:

```
Possibly NULL pointer passed to trusted R1
```

The verifier's own suggestion is correct: load the kptr into a register, NULL-check it, and only call the kfunc on the non-NULL path.

## Fix

Load `value->task` into a local variable, test it for NULL, and only acquire when it's non-NULL:

```c
SEC("tp_btf/task_newtask")
int BPF_PROG(entry, struct task_struct *task, u64 flags)
{
	struct task_struct *acquired, *kptr;
	struct map_value *value;

	value = helper_a(task);
	if (!value)
		return 0;

	kptr = value->task;
	if (!kptr)
		return 0;

	acquired = bpf_task_acquire(kptr);
	if (!acquired)
		return 0;

	bpf_task_release(acquired);
	return 0;
}
```

The explicit `if (!kptr) return 0;` forces the verifier to narrow the register from `rcu_ptr_or_null_task_struct` to a non-NULL pointer before it reaches `bpf_task_acquire()`, satisfying the kfunc's contract.

(Note: writing it as two statements — load then check — rather than calling `bpf_task_acquire(value->task)` inline is what guarantees the NULL check is applied to the same register that is passed to the kfunc.)
