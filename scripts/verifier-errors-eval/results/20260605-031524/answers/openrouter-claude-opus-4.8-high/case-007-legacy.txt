## Explanation

`slice_len` is a **global variable**, which the verifier models as a value read from the program's `.data` map. When the program loads it:

```
11: (61) r4 = *(u32 *)(r1 +0)   ; R4=scalar(... umax=0xffffffff ...)
```

R4 becomes a completely **unbounded** scalar (any value in `[0, 0xffffffff]`).

This R4 is then passed as the `len` argument to `bpf_dynptr_slice()`:

```c
hdr = bpf_dynptr_slice(&ptr, 0, buffer, slice_len);
```

`bpf_dynptr_slice()` may copy up to `len` bytes into the local `buffer[]`, which is only `sizeof(struct ethhdr)` bytes. Because the verifier cannot prove `len <= sizeof(buffer)`, it rejects the call:

```
R4 unbounded memory access, use 'var &= const' or 'if (var < const)'
R3 and R4 memory, len pair leads to invalid memory access
```

The verifier explicitly tells us the fix: bound the variable (`var &= const` or `if (var < const)`).

## Fix

Bound `slice_len` against the buffer size before the call so the verifier knows the length can never exceed the destination buffer:

```c
SEC("?tc")
int entry(struct __sk_buff *skb)
{
	struct bpf_dynptr ptr;
	struct ethhdr *hdr;
	char buffer[sizeof(*hdr)] = {};

	bpf_dynptr_from_skb(skb, 0, &ptr);

	if (slice_len > sizeof(buffer))
		return SK_DROP;

	hdr = bpf_dynptr_slice(&ptr, 0, buffer, slice_len);
	if (!hdr)
		return SK_DROP;

	return SK_PASS;
}
```

After `if (slice_len > sizeof(buffer)) return SK_DROP;`, the verifier narrows R4 to `umax = sizeof(buffer)`, so the `(buffer, slice_len)` mem/len pair is provably within bounds and the call is accepted.

(An equivalent minimal alternative is masking: `slice_len &= sizeof(buffer) - 1;` if the size is a power of two — but the explicit bound check is clearer and works for any size.)
