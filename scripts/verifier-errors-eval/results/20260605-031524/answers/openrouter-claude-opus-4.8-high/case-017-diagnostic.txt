## Explanation

`bpf_local_irq_save`/`bpf_local_irq_restore` model IRQ-disabled regions as a nested resource that the verifier tracks with a strict **LIFO (last-in, first-out)** discipline. Each `save` pushes an IRQ flag id; each `restore` must pop the most recently saved one.

In the source:

```c
bpf_local_irq_save(&flags1);    // pushes id=1
bpf_local_irq_save(&flags2);    // pushes id=2  (now active)
bpf_local_irq_restore(&flags1); // tries to pop id=1  <-- WRONG
bpf_local_irq_restore(&flags2);
```

The first restore targets `flags1` (id=1) while the currently active region is `flags2` (id=2). That violates LIFO ordering, so the verifier rejects it:

```
cannot restore irq state out of order, expected id=2 acquired at insn_idx=7
```

## Fix

Restore the nested flags in reverse order of saving — restore `flags2` first, then `flags1`:

```c
SEC("?tc")
int entry(struct __sk_buff *ctx)
{
	unsigned long flags1, flags2;

	bpf_local_irq_save(&flags1);
	bpf_local_irq_save(&flags2);
	bpf_local_irq_restore(&flags2);
	bpf_local_irq_restore(&flags1);
	return 0;
}
```

This is the smallest possible change (swap the two `restore` calls) and makes the save/restore sequence properly nested LIFO, satisfying the verifier's resource-lifetime safety check.
