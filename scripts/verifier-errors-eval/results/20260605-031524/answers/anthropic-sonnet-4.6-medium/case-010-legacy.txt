## Explanation

In `helper_b`, the call `helper_c(val, skb + 1)` passes a **pointer-arithmetic-modified** context pointer (`skb + 1`, which the compiler turns into `skb + 192` since `sizeof(struct __sk_buff) == 192`). The BPF verifier tracks this as `ctx(imm=192)` and refuses to let `helper_c` dereference it because dereferencing an offset/modified `ctx` pointer is not allowed — you must always pass the original, unmodified context pointer.

The verifier message confirms this:
```
21: (07) r6 += 192                    ; R6=ctx(imm=192)
...
dereference of modified ctx ptr R2 off=192 disallowed
```

## Fix

Change `skb + 1` to `skb` in `helper_b`:

```c
__attribute__((noinline))
int helper_b(int val, struct __sk_buff *skb)
{
	return helper_a(skb) + helper_c(val, skb);
}
```

This passes the unmodified context pointer to `helper_c`, which the verifier will accept.
