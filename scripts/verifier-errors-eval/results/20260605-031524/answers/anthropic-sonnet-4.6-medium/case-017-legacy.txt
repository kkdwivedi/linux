## Explanation

The BPF verifier enforces that `bpf_local_irq_save`/`bpf_local_irq_restore` pairs follow **LIFO (stack) order**, just like real IRQ flag nesting must work.

- `flags1` was saved first → assigned id=1  
- `flags2` was saved second → assigned id=2  

The verifier therefore expects `flags2` (id=2, the most-recently saved) to be restored **before** `flags1`. The code restores them in the wrong order (`flags1` first, then `flags2`), causing the error:

```
cannot restore irq state out of order, expected id=2 acquired at insn_idx=7
```

## Fix

Swap the two `bpf_local_irq_restore` calls so they follow LIFO order:

```c
--- a/case.c
+++ b/case.c
@@ -9,7 +9,7 @@ int entry(struct __sk_buff *ctx)
 	bpf_local_irq_save(&flags1);
 	bpf_local_irq_save(&flags2);
-	bpf_local_irq_restore(&flags1);
 	bpf_local_irq_restore(&flags2);
+	bpf_local_irq_restore(&flags1);
 	return 0;
 }
```

`flags2` must be restored first (it was saved last), then `flags1`.
