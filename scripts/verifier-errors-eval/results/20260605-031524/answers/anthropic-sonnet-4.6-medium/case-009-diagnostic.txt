## Explanation

The verifier sees `value->task` as `rcu_ptr_or_null_task_struct` — a kptr that may be NULL — because it was stored via `bpf_kptr_xchg` and retrieved from a map. `bpf_task_acquire` requires a **non-NULL** trusted pointer, so the call is rejected.

The fix is simply to NULL-check `value->task` before passing it to `bpf_task_acquire`.

## Patch

```c
SEC("tp_btf/task_newtask")
int BPF_PROG(entry, struct task_struct *task, u64 flags)
{
	struct task_struct *acquired;
	struct map_value *value;

	value = helper_a(task);
	if (!value)
		return 0;

+	if (!value->task)
+		return 0;
+
	acquired = bpf_task_acquire(value->task);
	if (!acquired)
		return 0;

	bpf_task_release(acquired);
	return 0;
}
```

Adding `if (!value->task) return 0;` before the `bpf_task_acquire` call narrows the type of `value->task` from `rcu_ptr_or_null_task_struct` to `rcu_ptr_task_struct` (non-NULL), satisfying the verifier's requirement for a trusted non-NULL pointer.
