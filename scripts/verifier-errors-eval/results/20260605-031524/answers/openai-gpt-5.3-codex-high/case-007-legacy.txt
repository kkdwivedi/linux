The verifier is rejecting this at:

```c
hdr = bpf_dynptr_slice(&ptr, 0, buffer, slice_len);
```

### Why it fails

`slice_len` is a **writable global** (`.data` map), so verifier does **not** trust its initializer (`sizeof(struct ethhdr)`).  
In the log, `R4` (the length arg) is:

- `smin=0, umax=0xffffffff` (unbounded)

For `bpf_dynptr_slice()`, `(buffer, len)` must be proven safe. Your `buffer` is a small stack array (14 bytes), but `len` is treated as potentially huge, so verifier reports:

- `R4 unbounded memory access`
- `R3 and R4 memory, len pair leads to invalid memory access`

---

### Smallest likely fix

Load `slice_len` once into a local, bound-check it against `sizeof(buffer)`, then pass that bounded local to the helper.

```diff
 SEC("?tc")
 int entry(struct __sk_buff *skb)
 {
 	struct bpf_dynptr ptr;
 	struct ethhdr *hdr;
 	char buffer[sizeof(*hdr)] = {};
+	__u32 len = slice_len;
+
+	if (len > sizeof(buffer))
+		return SK_DROP;
 
 	bpf_dynptr_from_skb(skb, 0, &ptr);
 
-	hdr = bpf_dynptr_slice(&ptr, 0, buffer, slice_len);
+	hdr = bpf_dynptr_slice(&ptr, 0, buffer, len);
 	if (!hdr)
 		return SK_DROP;
 
 	return SK_PASS;
 }
```

This gives verifier a proven upper bound for `len`, so the stack memory access pair should become valid.
