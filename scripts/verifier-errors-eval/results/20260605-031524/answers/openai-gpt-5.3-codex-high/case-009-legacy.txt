The verifier is failing at this call in `entry()`:

```c
acquired = bpf_task_acquire(value->task);
```

From the log:

- `value` is known non-NULL (after `if (!v)` check),
- but `value->task` is loaded as `rcu_ptr_or_null_task_struct`,
- and `bpf_task_acquire()` requires a non-NULL pointer argument at call time.

So verifier rejects with:

> Possibly NULL pointer passed to trusted R1

It does **not** infer that `map_insert()` previously set this field, because map contents are mutable and the loaded kptr is still considered nullable.

### Smallest likely fix

Load `value->task` into a local, check it for NULL, then call `bpf_task_acquire()` on that checked local.

```diff
@@ SEC("tp_btf/task_newtask")
 int BPF_PROG(entry, struct task_struct *task, u64 flags)
 {
-	struct task_struct *acquired;
+	struct task_struct *acquired, *stored;
 	struct map_value *value;
@@
 	value = helper_a(task);
 	if (!value)
 		return 0;
 
-	acquired = bpf_task_acquire(value->task);
+	stored = value->task;
+	if (!stored)
+		return 0;
+
+	acquired = bpf_task_acquire(stored);
 	if (!acquired)
 		return 0;
 
 	bpf_task_release(acquired);
 	return 0;
 }
```

This is the minimal source-level change that should satisfy the verifier for this failure.
