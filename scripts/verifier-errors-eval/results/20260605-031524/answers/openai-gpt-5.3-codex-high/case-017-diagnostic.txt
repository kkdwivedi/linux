The verifier error is due to **nested IRQ save/restore ordering**.

### Why it fails

You do:

```c
bpf_local_irq_save(&flags1); // acquire #1
bpf_local_irq_save(&flags2); // acquire #2
bpf_local_irq_restore(&flags1); // tries to release #1 first  <-- wrong
bpf_local_irq_restore(&flags2);
```

`bpf_local_irq_save/restore` is tracked like a stack by the verifier.  
Nested saves must be restored in **LIFO** order (last saved, first restored).

So after saving `flags2`, the next valid restore is `&flags2`, not `&flags1`.  
That matches the log: “expected id=2 acquired at insn_idx=7”.

---

### Smallest fix

Swap the two restore calls:

```diff
 SEC("?tc")
 int entry(struct __sk_buff *ctx)
 {
 	unsigned long flags1, flags2;

 	bpf_local_irq_save(&flags1);
 	bpf_local_irq_save(&flags2);
-	bpf_local_irq_restore(&flags1);
-	bpf_local_irq_restore(&flags2);
+	bpf_local_irq_restore(&flags2);
+	bpf_local_irq_restore(&flags1);
 	return 0;
 }
```

This should satisfy the verifier’s resource-lifetime check.
