## Explanation of the Verifier Failure

The BPF verifier enforces strict **last-in, first-out (LIFO) ordering** for IRQ flag save/restore operations. This is a resource lifetime safety requirement.

In the code:
1. `bpf_local_irq_save(&flags1)` is called first (insn 3, id=1)
2. `bpf_local_irq_save(&flags2)` is called second (insn 7, id=2)
3. `bpf_local_irq_restore(&flags1)` is called third (insn 9)

The problem: You're trying to restore `flags1` (id=1) while `flags2` (id=2) is still active. The verifier requires that the most recently acquired IRQ state (id=2) must be restored first. This is analogous to stack unwinding—you must undo operations in reverse order.

The verifier message confirms: "expected id=2 acquired at insn_idx=7" - meaning it expects to restore flags2 before flags1.

## Fix

Swap the order of the restore calls to respect LIFO ordering:

```c
#include <vmlinux.h>
#include <bpf/bpf_helpers.h>

SEC("?tc")
int entry(struct __sk_buff *ctx)
{
	unsigned long flags1, flags2;

	bpf_local_irq_save(&flags1);
	bpf_local_irq_save(&flags2);
	bpf_local_irq_restore(&flags2);
	bpf_local_irq_restore(&flags1);
	return 0;
}
```

**Changes:** Lines 248-249 swapped so that `flags2` is restored before `flags1`.

**Why this works:** The restore order now matches the reverse of the save order (LIFO), satisfying the verifier's resource lifetime safety requirements.
